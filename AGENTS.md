# Canonical repository instructions

## Scope

- This repository (`git-haya-ora/dsh-discord-remote-agents`) is the canonical source, test, documentation and supported DSH bundle development home. Do not resume product development in the retired private checkout.
- Implement Discord first according to [specification](<specification.md>). Preserve Telegram code and regression tests; expansion is deferred.
- Coordinate ownership, independent review and publication. One integrator owns shared Git changes; serialize index/commit/push operations. Contributors must agree file ownership before parallel edits and must not delegate further without coordination.

## Security

- This repository is PUBLIC. Never copy private Git history, `.env`, real configs, credentials, databases, protected-secret blobs, logs, transcripts, backups, research extracts, local identities or real user paths into it. Example configuration and test identities must be synthetic.
- Rotate any Discord token exposed in chat. Never reuse, print or persist it here; fresh tokens belong only in a verified local protected store.
- Preserve exact Native Session identity, pinned destinations, authorization, and unknown/no-replay semantics. Do not invent Native APIs, bypass authentication, modify ASAR, weaken storage ACL checks, or kill shared DSH processes.
- Unsupported history/model/settings/context contracts, C/model controls, DM-only operation, full OUT08 retention, and live acceptance remain gaps. Mock tests do not establish live integration.

## Source and distribution

- Canonical TypeScript is in [src](<src/>); plugin source is in [plugin source](<packages/discord-plugin/>). Edit these, not generated root JS or [runtime](<runtime/>).
- Preserve the root npm/DSH exports, explicit `files`, `dsh.bundle.patch`, `dsh.client`, and root Cordis patch. GitHub bundle installation must not require build/lifecycle scripts.
- Node >=22.23.0: `npm ci --ignore-scripts`, `npm test`, `npm run verify:source`, `npm audit`, `npm run pack:plugin`. Inspect the resulting archive with `node tools/verify-bundle.mjs <archive>`.
- Root distribution and [SHA256 inventory](<MANIFEST.sha256>) are regenerated by `npm run build`. Keep root and canonical plugin package identity/contracts in sync. Never add deployment or automatic command registration to build/test.

## Publication

- Work on a review branch. Stage explicit paths, inspect staged diff and `node tools/verify-public-source.mjs --staged`, then obtain independent review closure before public push.
- Check exact account/remote and branch policies; use normal commits/merges only, never force push. Never publish the npm registry or register live Discord commands without a separate request.
- Verify remote SHA equals local HEAD after publishing. Preserve existing public history and releases. Document unverified/live gaps honestly.
