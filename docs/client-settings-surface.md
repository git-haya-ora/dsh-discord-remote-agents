## Scope and authority

The user approved the [restricted profile](<limited-profile.md>) on 2026-10-14. This supersedes the previous static-only [notice brief](<client-notice-surface.md>) for the new connected Client. It does not assert independent owner/admin identity, atomic Desktop admission or completed live acceptance.

## Mode: Operate

Help a single authenticated DSH operator configure and explicitly start a Discord receiver without leaving the existing Plugin Manager. On 2026-10-14 the user requested simpler use: make the first path **save settings → add Discord commands → start connection**, with the necessary instructions inline. Saving verifies the Bot, so a separate token test is optional, not a required extra secret entry. Saving must not imply a live connection or Native execution. The short [quick start](<quickstart.md>) is the user-facing entry; development and recovery details remain available separately.

## Incumbent world

- Use the official `plugins.bundle.config` slot keyed by this bundle package. Preserve DSH's surrounding Plugin Manager, typography, current colors, form expectations and lifecycle.
- No replacement application shell, private server, new palette, display fonts, raster assets, ornamental dashboard metrics or fabricated connection lights.
- Put initial configuration before registration/start controls; make the next action clear without claiming server-side progress that is not known. Use ordinary labeled workspace name/folder rows rather than an `alias=path` mini-language. Preserve multiple explicit allowlist entries and existing workspace settings.
- Fold optional testing, autostart, reconnect and diagnostics into native details; place secret deletion in its own disclosed danger area. Keep current errors and the single-operator/non-atomic/PC-only limits visible. Labels remain visible; error and pending state do not rely on color.
- Unsaved settings or a newly entered token must block registration/start/reconnect against the previous saved configuration. Offer explicit save/discard; never silently save, send a candidate token or start a receiver.
- Support narrow panels through wrapping/stacking and full-width inputs. No secrets in overflow, tooltips, URLs or external links.

## Behavior contract

- Host status is the source of truth. Unknown/unavailable is not connected; an empty list or zero must not silently replace a failed request.
- Show the single-operator/non-atomic constraints next to connection controls. Approval/cancel/attachments/artifacts are unavailable; instruct the user to use PC DSH.
- Token input is password/write-only, local and transient. Empty means keep. Submission clears the field immediately, including on failure; unmount aborts every pending request and clears transient references. No clipboard automation, browser storage, logging or credential readback.
- Save and start are distinct. Start/stop/reconnect are about the Discord receiver, not a DSH Run. Mark busy requests and prevent duplicate submissions.
- Registration, deletion, start and reconnect require explicit confirmation. Autostart needs separate consent and only arms after a confirmed successful manual start at the saved revision; save/stop/delete disarm it. Saving or deleting a secret stops the receiver, not a Native Run. Revision conflicts require refresh/review rather than blind retry of mutations.
- Nonsecret allowlists and workspace aliases are explicit, not inferred from local sessions or a token. Folder allowlisting is not an execution sandbox.
- Localize operator-facing labels through the existing locale system. Native semantic fields, visible focus, live status/error messaging and cleanup on disposal are required.

## Evidence boundary

Source/registration tests are not screenshot, accessibility, Plugin Manager install or live Discord proof. Verify the shipped existing GUI after official installation and refresh when possible. Without authenticated browser access, record **recapture / live verification pending**, never a visually approved or installed result. Do not start a replacement server to obtain a screenshot.
