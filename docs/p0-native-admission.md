# Native admission limitations

Prompt acceptance is not a stable Native Run receipt or proof of cross-Desktop atomic admission. Plugin-local locking and status-then-submit cannot serialize independent Desktop callers. Do not substitute Session-level cancellation for Run-scoped cancellation.

Native Session history cursors alone do not prove a Run-scoped resumable event contract. Native approval interactions must not be forged, replayed or bypassed. Missing contracts fail closed; unknown outcomes are not automatically replayed.

Full-spec acceptance requires a shared Host linearization point used by Desktop and connector, durable request/receipt correlation across crashes, targeted cancellation and verified Run/event/approval association. These remain upstream contract and live verification gaps, not APIs to invent.

The restricted bridge requires alternating Desktop and Discord use. Mock tests do not establish live coordination. See [limited profile](<limited-profile.md>) and [specification](<../specification.md>).
