# Host-only protected text payloads — internal producer

**Isolated implementation and synthetic verification completed.** This is an isolated producer for the protected references required by [the specification](<../specification.md#L1206-L1220>), not a DSH service, Native admission contract, public management API or sender. It does not enable any Host capability or connected Client operation.

## Scope

- Text-only prompt and notification bodies: strict own-data schema, bounded identity context, exact well-formed Unicode and line breaks. No silent truncation, Unicode normalization or attachment removal. Attachments, streamed output, large output artifacts and files require separate verified producers.
- Fixed-order canonical UTF-8 envelope and SHA-256 digest bind kind, context and exact body. The descriptor's `digest` is an **internal envelope fingerprint**, distinct from the future RFC-A normalized body/attachment/Session payload digest. No upstream compatibility or interchangeability is verified. Matching structure/digest is not authorization or authoritative Native event provenance.
- Random opaque 256-bit references and metadata-only creation results. Host-only reads must verify expected kind, context, digest and canonical encoding before returning plaintext internally. Never expose these reads, refs or paths through Client/Remote.
- Conservative primitive caps: 20,000 Unicode scalar values, 80,000 body UTF-8 bytes and 96 KiB canonical envelope. Escaping and bounded metadata also count toward envelope size. Reject overflows with a constant code; do not claim full output/artifact support.

## Separate protection boundary

The producer uses a dedicated payload helper, root, `payload-<64 lowercase hex>.dpapi` names and payload-specific CurrentUser DPAPI entropy. The existing [token provider and helper](<windows-secrets.md>) remain unchanged. Payload roots reject token, journal and other unexpected files before writing; copied ciphertext must not bypass kind/context/digest verification.

Private SID/ACL, ancestor, reparse and logging-policy gates remain mandatory. The payload helper also validates leaf attributes and single-link identity on opened file handles using documented Win32 `GetFileInformationByHandle`; this is not a DSH API or full filesystem race-proof broker. No plaintext fallback, environment lookup, real credentials, arbitrary download or network activity is allowed. Only a missing root under an acceptable existing parent may be created with restrictive ACLs; existing ACLs are not repaired to make tests pass. Only explicit path/ACL/namespace/handle validation failures use the unsafe-path code; generic file creation, read/write/flush/dispose and helper/API failures must not be hidden as path-refusal skips.

This is not a sandbox against same-SID code, administrator/SYSTEM, memory inspection or a privileged path race. JS plaintext copies cannot be guaranteed zeroized. The old trusted token provider accepts a caller-chosen root and could contaminate a misconfigured payload root; distinct names/entropy and subsequent refusal do not imply symmetric protection against trusted Host misuse. A dedicated new root is a caller precondition.

## DB and lifecycle boundaries

Protect and validate the blob **before** entering [the unified journal transaction](<run-outbox-journal-foundation.md>). The raw producer/journal APIs leave this ordering to the caller; the [internal connection adapter](<protected-run-outbox-foundation.md>) creates and read-validates the envelope before entering SQL. It durably separates the prompt envelope fingerprint from the externally verified Native request digest. On protection or verification failure it must not enter SQL. Store and SQL are not a distributed atomic transaction: crash or failed/duplicate DB admission can leave an encrypted orphan. Replaying an input or terminal may create a fresh ref while the journal returns the original pinned Run/pair; do not delete either ref without checking ownership/reference status. The unified input dedupe excludes only recreated payload refs and mutable generation/lease fields while requiring the original immutable metadata and both digests to match.

This increment deliberately has no retirement, expiry or sweep API, reference count or total-store quota. Whole-root namespace/leaf inspection is not a 10,000-Run performance benchmark. Seven-day resolved payload retention, ninety-day Run/audit/tombstone retention and preservation of referenced/unknown/unsent material require an authenticated, reference-aware lifecycle coordinator. No timer may infer acceptance, completion or release from elapsed time.
